# W.VOTE — голосование прямо в чате w.tv

Статический сайт: стример вводит ссылку на свой канал, сайт читает публичный чат w.tv,
зрители пишут слово-голос — и сайт считает голоса, а после раунда начисляет очки.

* Сайт: `https://xiqima.github.io/w-vote/`
* Бэкенда нет, аккаунтов и паролей нет. Все очки, раунды и настройки лежат в `localStorage`
  конкретного браузера.
* Сборки нет: обычные `<script>`, открывается даже двойным щелчком по `index.html`.

## Два режима

| Режим | Что пишут зрители | Кто получает очки |
|---|---|---|
| **Опрос** | одно из 2–100 своих вариантов (`да`, `нет`, `синий`…) | те, кто выбрал победивший вариант |
| **Рулетка** | слово участия (по умолчанию `+`) | победитель, выбранный случайно (можно выключить) |

Опрос заменил прежний режим «победа / поражение»: два варианта — это тот же опрос, только
настраивается что угодно. Старые раунды этого режима продолжают открываться, считаться и
выгружаться как раньше, а слова из старых настроек при обновлении переносятся в варианты опроса.

В опросе есть переключатель **«Победитель — вариант с наибольшим числом голосов»**: если он включён,
итог объявляется сразу после остановки приёма (при ничьей сайт честно попросит выбрать вариант вручную).

**Сколько очков даёт раунд** задаётся числом в настройках (0–100, по умолчанию 1). Значение
запоминается в самом раунде, поэтому изменение настройки не переписывает уже начисленные очки.

**Рулетка** — это розыгрыш: стример останавливает приём, жмёт «Крутить», ники прокручиваются и
сайт выбирает случайного участника. Прокрутка каждый раз разная (пять вариантов анимации),
а кнопка **«Перевыбрать»** перекручивает раунд и пересчитывает очки.

Слова-голоса могут быть и из символов: `+`, `++`, `?!`. Голосом считается сообщение **целиком**
(с точностью до регистра, пунктуации по краям и эмоутов), поэтому «я за +» не засчитывается.

## Раунд в четыре шага

1. **«Новый раунд»** — раунд создан, но сообщения ещё не считаются: можно поправить варианты,
   очки и таймер.
2. **«Начать приём»** — с этой секунды слова из чата учитываются. Пока приём идёт, режим
   переключить нельзя (кнопки блокируются), чтобы раунд не «переехал» на другие варианты.
3. **«Остановить приём»** — голоса фиксируются (можно «Возобновить»).
   Если включён таймер, приём закроется сам.
4. **Объявить итог** — вариант опроса или «Крутить» в рулетке.

**Таймер раунда** — необязательный: длительность 5–3600 секунд (есть кнопки 30 с / 1 мин / 3 мин / 5 мин).
Отсчёт виден в карточке раунда, по нулю приём голосов закрывается автоматически; объявить итог
всё равно нужно вручную (или включить «победитель по большинству»).

Плюс: ручная правка очков, экспорт `.xlsx` (листы «Лидеры», «Раунды», «Сводка») / `.csv` / `.txt`,
резервная копия JSON, история раундов, режим переголосования. Объявление исхода сопровождается
короткой анимацией — без звука, с уважением к `prefers-reduced-motion`.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка: экран подключения + рабочая панель |
| `style.css` | оформление, тёмная тема, адаптив |
| `core.js` | логика без DOM: сообщения, голоса, очки, фазы и режимы раунда, localStorage, **сеть к w.tv**, сборка xlsx |
| `app.js` | интерфейс: рендер, обработчики, опрос чата, экспорт, диагностика связи |
| `config.js` | `window.WTV_DEFAULT_PROXY` — прокси по умолчанию (пусто = только публичные) |
| `optional-proxy/` | свой посредник на Cloudflare Workers (не обязателен) |
| `tests/` | проверки на Node без зависимостей |


## Настройки связи — прямо на странице подключения

Блок **«Настройки связи: посредники, свой прокси, сброс»** есть на первом экране (до подключения
канала) и дублируется в рабочей панели, в «Данные и подключение». Внутри:

* **галочки «какие посредники использовать»** — по умолчанию включены все. Снятая галочка значит
  «этим способом не ходить»: удобно, когда посредник отдаёт «лимит запросов» и мешает остальным;
* **свой прокси** — адрес с шаблоном `{url}` (инструкция ниже);
* **«Проверить связь»** — отчёт по каждому посреднику: `✓ 0.6 с`, `✗ HTTP 403`, `✗ не ответил`, `✗ ответ не JSON`;
* **«Сбросить всё (как в первый раз)»** — стирает из браузера все данные сайта: каналы, раунды, очки,
  настройки связи, кэш канала и запомненных посредников. Сайт возвращается к экрану подключения,
  как при первом заходе. Ключи других сайтов не затрагиваются.

Настройки связи общие для браузера (это свойство сети, а не канала) и лежат в `localStorage` под ключом
`wtv_vote_net_v1`: `{preferred, health, proxy, enabled}`, где в `enabled` записаны только **выключенные**
способы — поэтому новые посредники появляются у людей сразу включёнными.

## Почему «через посредника» и что делать, если не подключается

У `chats-service.w.tv` и `profiles-service.w.tv` заголовок `Access-Control-Allow-Origin` отдаётся только
для `https://w.tv`, поэтому браузер не может обратиться к ним с нашего сайта. Сайт пробует несколько
публичных посредников (r.jina.ai, allorigins, cors.lol, codetabs) **одновременно**, берёт первый валидный
ответ, запоминает рабочий способ в `localStorage` и дальше ходит через него. Если посредник подводит,
он уходит в «паузу», но сайт не сдаётся.

Если не подключается (частая история там, где провайдер режет зарубежные сервисы):

1. **Включить VPN** и нажать «Повторить».
2. **Проверить связь** — сразу видно, кто именно не отвечает; лишние способы можно снять галочками.
3. **Вставить ID канала вместо ника** — запасной путь без сервиса профилей (ID виден в «Данные и подключение»).
4. **Поднять свой прокси** один раз — 3 минуты, бесплатно, без установки программ:
   1. <https://dash.cloudflare.com/sign-up> — регистрация по e-mail, карта не нужна.
   2. **Compute (Workers)** → **Create** → **Start with Hello World!** → **Deploy**.
   3. **Edit code** → выделить всё → вставить [`optional-proxy/worker.js`](optional-proxy/worker.js)
      (тот же код есть на сайте, кнопка «Скопировать код прокси») → **Deploy**.
   4. Адрес `https://имя.аккаунт.workers.dev` + `/?url={url}` → вставить в «Свой прокси для чата».
   5. Кнопка **«ссылка для зрителей»** рядом — копирует адрес с `?proxy=…`, по которому посредник
      подхватывается у зрителей сам.

   Лимиты бесплатного плана Workers: 100 000 запросов в сутки и 10 мс CPU на запрос — время ожидания
   ответа w.tv в CPU не считается, поэтому нашему воркеру этого хватает с большим запасом.

> Воркер должен быть **модульным** (`export default { async fetch() {} }`), как в `optional-proxy/worker.js`.
> Старый вариант с `addEventListener('fetch', …)` разворачивается, но на каждый запрос отдаёт ошибку.

Хочешь применить свой прокси для всех и без ссылок — впиши шаблон в `config.js`:

```js
window.WTV_DEFAULT_PROXY = 'https://имя.аккаунт.workers.dev/?url={url}';
```

## Проверки

```bash
node tests/core.test.js            # логика: голоса, очки, миграция, сеть и настройки связи
node tests/phases-export.test.js   # фазы раунда, экспорт csv/txt/xlsx
node tests/modes-timer.test.js     # режимы, фазы (готов/приём/итог), очки, таймер, настройки
```

Экспорт `.xlsx` собирается вручную (`zipStore` + `makeXlsx`) и должен открываться `openpyxl`
без предупреждений, с тремя листами: «Лидеры», «Раунды», «Сводка».

## Разработка

* Никаких ES-модулей и npm-зависимостей: только классические `<script>` и `window.WVote`.
* Новая сетевая функция — только через `requestWithRetry()` в `core.js`, иначе она не получит
  цепочку посредников, повторы и диагностику.
* Демо-режим без сети: `index.html?demo=1`.
* Добавил функцию в `core.js` — добавь её в `window.WVote`.
* Новые настройки канала живут в `state.settings` и попадают туда через `normalizeSettings()`:
  старые сохранения и резервные копии без новых полей не ломаются.
* Раунд хранит снимок своих правил (`mode`, `options`/`entryWords`, `points`, `autoWinner`,
  `timerSeconds`, `awardWinner`), поэтому смена настроек не переписывает уже идущий раунд и историю.
  Пока раунд в фазе `ready` (создан, но не начат), правки настроек в него переносятся.
* Фазы раунда: `ready` (`openedAt` пуст) → `voting` → `awaiting` → `finished`; старые раунды
  без `openedAt` читаются как начатые, поэтому обновление ничего не ломает.
* Голос считается по ключу варианта (`p1…p100` у опроса, `enter` у рулетки, у старых раундов
  классики — `win`/`lose`), а очки начисляет `computeScores()`:
  сумма `points` угаданных раундов + победы в рулетке + `adjust`.
