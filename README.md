# W.VOTE — голосование прямо в чате w.tv

Статический сайт: стример вводит ссылку на свой канал, сайт читает публичный чат w.tv,
зрители пишут слово-голос (`win` / `lose`), сайт считает голоса и ведёт таблицу лидеров.

* Сайт: `https://xiqima.github.io/w-vote/`
* Бэкенда нет, аккаунтов и паролей нет. Все очки, раунды и настройки лежат в `localStorage`
  конкретного браузера.
* Сборки нет: обычные `<script>`, открывается даже двойным щелчком по `index.html`.

## Раунд в три шага

1. **Начать голосование** — зрители пишут слово-голос, голоса считаются.
2. **Остановить приём голосов** — голоса фиксируются (можно «Возобновить»).
3. **Была победа / Было поражение** — угадавшим +1 очко.

Плюс: ручная правка очков, экспорт `.xlsx` (листы «Лидеры», «Раунды», «Сводка») / `.csv` / `.txt`,
резервная копия JSON, история раундов, свои слова-голоса, режим переголосования.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка: экран подключения + рабочая панель |
| `style.css` | оформление, тёмная тема, адаптив |
| `core.js` | логика без DOM: сообщения, голоса, очки, localStorage, **сеть к w.tv**, сборка xlsx |
| `app.js` | интерфейс: рендер, обработчики, опрос чата, экспорт, диагностика связи |
| `config.js` | `window.WTV_DEFAULT_PROXY` — прокси по умолчанию (пусто = только публичные) |
| `optional-proxy/` | свой посредник на Cloudflare Workers (не обязателен) |
| `tests/` | проверки на Node без зависимостей |

На GitHub Pages достаточно пяти файлов из корня (`index.html`, `style.css`, `core.js`, `app.js`,
`config.js`). Папки `optional-proxy/` и `tests/` сайту не нужны, но пусть лежат в репозитории.

## Почему «через посредника» и что делать, если не подключается

У `chats-service.w.tv` и `profiles-service.w.tv` заголовок `Access-Control-Allow-Origin`
отдаётся только для `https://w.tv`, поэтому браузер не может обратиться к ним с нашего сайта.
Сайт пробует несколько публичных посредников (r.jina.ai, allorigins, cors.lol, codetabs)
**одновременно**, берёт первый валидный ответ и запоминает рабочий способ в `localStorage`.
Если посредник подводит — он уходит в «паузу», но сайт не сдаётся.

Если не подключается (частая история у зрителей/стримеров из Беларуси и РФ, где провайдер
режет часть зарубежных сервисов):

1. **Включить VPN** и нажать «Повторить» — на практике помогает чаще всего.
2. **Проверить связь** (кнопка на экране ошибки и в «Данные и подключение») — покажет по каждому
   посреднику, что именно происходит: `HTTP 403`, «не ответил за 12 с», «ответ не JSON».
3. **Вставить ID канала вместо ника** — это запасной путь: `profiles-service` не нужен,
   сайт сразу читает чат по ID. ID виден в блоке «Данные и подключение» на рабочей панели
   и в адресе страницы (`?c=<ID>`), его же можно передать другому устройству ссылкой.
4. **Поднять свой посредник** — 2 минуты, бесплатно, без установки программ:

   [![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/xiqima/w-vote/tree/main/optional-proxy)

   либо вручную: `dash.cloudflare.com` → Workers & Pages → Create → Worker → Deploy →
   Edit code → вставить `optional-proxy/worker.js` → Deploy. Получится адрес
   `https://имя.аккаунт.workers.dev`, его нужно вписать в
   «Данные и подключение» → «Свой прокси для чата» в виде
   `https://имя.аккаунт.workers.dev/?url={url}`.

> Важно: воркер должен быть **модульным** (`export default { async fetch() {} }`), как в
> `optional-proxy/worker.js`. Старый вариант с `addEventListener('fetch', …)` в новых воркерах
> разворачивается, но на каждый запрос отдаёт ошибку — из-за этого «свой прокси» может
> выглядеть рабочим и при этом не работать.

## Проверки

```bash
node tests/core.test.js            # логика: голоса, очки, миграция, сеть (на подставном fetch)
node tests/phases-export.test.js   # фазы раунда, экспорт csv/txt/xlsx
```

Экспорт `.xlsx` собирается вручную (`zipStore` + `makeXlsx`, без библиотек) и должен открываться
`openpyxl` без предупреждений, с тремя листами.

## Разработка

* Никаких ES-модулей и npm-зависимостей: только классические `<script>` и `window.WVote`.
* Новая сетевая функция — только через `requestWithRetry()` в `core.js`, иначе она не получит
  цепочку посредников, повторы и диагностику.
* Демо-режим для проверки интерфейса без сети: `index.html?demo=1`.
* Добавил функцию в `core.js` — добавь её в `window.WVote`.
